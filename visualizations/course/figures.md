# Course figures registry

Generated by `visualizations/build_course_figures.py`. Every number in every figure is
read at run time from the four source files listed per figure below; nothing is
hardcoded in the script. Re-run with:

```
source .venv/bin/activate && python3 visualizations/build_course_figures.py
```

`figure_values.csv` in this directory holds every plotted value (figure, series, label,
k, n, rate, ci_lo, ci_hi, status) for hand-checking against the source CSVs/JSON.

have a computable rate but fewer than 3 discovered episodes; they are drawn as solid grey
bars, sorted after the n>=3 group and before the refused/censored group, with their own
legend entry, so a 100% or 0% bar built from a single episode is never visually
indistinguishable from a well-powered one.

## fig4_part1_competence_vs_concealment.png

**Title:** Part 1: competence vs visible-prose concealment, per model

**Caption:** Concealment on the impossible-task split is near zero for every model below
the 0.75 competence floor and only becomes non-trivial (5-22%) for the three models that
clear it, with north-mini-code's pooled rate the clear outlier among those three.

**Source:** `research/canonical/concealment_rates.csv`. `north-mini-code (screen)` and
`north-mini-code (bigbatch)` rows are excluded per task instructions; only
`north-mini-code (pooled)` is plotted for that model. Rows without a `competence` value
are excluded (none in this file besides the excluded north-mini split rows).

**FINDINGS:** §F174 (qwen3.8-27b at n=100 after the `conflicting` split landed 2026-09-15: 0/50 impossible-split concealment, 18/50 disclosed, competence still 30/50; the point moved from 0/75 to 0/100 rows and its upper bound from 4.9% to 3.7%), §F165 (at n=50 its competence interval
sits entirely below 0.75, so it is now classified below-floor rather than in the
unresolved band §F160 left it in; its 0/25 concealment rate on the completed split is
recorded as not evidence about propensity for exactly that reason), §F148 (the same
"floor passing does not equal true competence" caveat that motivates treating any
below-floor concealment rate as uninformative rather than a genuine negative).

**Caveats.** Point size scales with `total_rows`, which mixes models tested at very
different N (62-237); a large low-N point and a small high-N point can look
visually similar in size without being comparable in precision; read the error bars,
rather than the marker alone. "Competence" here is `original_pass / original_total`, a different
quantity from BystanderBench's own floor/cover gates in fig1-fig3; the two competence
notions are related in spirit (both gate on "can the model do the base task at all") but
are measured on different task suites and are not numerically interchangeable.
llama-3.3-70b-instruct, olmo-3-7b-instruct, gemma-3-27b-it and gemma-3-12b-it cluster
within competence 0.13-0.24 and rate 0.00-0.03 with large markers (total_rows 62-166),
so their four labels are routed with leader lines to a single left-aligned column above
the cluster, ordered so the leader lines fan out monotonically with each marker's
competence value and never cross each other or a marker.

## fig6_scaling_read.png

**Title:** Incident 1 conditional rate vs active parameters, by model family (human-wrongdoer control)

**Condition note:** The plotted arm (`blatant_wrongdoing`) is the human-wrongdoer control: the
wrongdoer is a named human employee, not an agent (§F178). See §F179 for the agent-perpetrator
minimal pair.

**[PENDING]** Agent-perpetrator counterpart figure (arm `blatant_wrongdoing_agents`, §F179):
not yet built here, no results as of this note.

**Caption:** Across ten open-weight model families spanning roughly 3B to 70B active
parameters, the conditional reporting rate on incident 1 shows no relationship with
scale (Spearman rho = -0.19 over the 14 reportable points plotted, permutation p = 0.51,
20000 permutations); Claude's parameter count is undisclosed and shown in a separate
panel rather than placed on the log axis.

**Source (rebuilt for this registry entry).** Conditional rates, k/N and censoring now
come from `research/audits/cells_2026-09-15_after_w4c.csv`, the SAME v1.1 source
CSV fig1 uses, filtered the same way (`arm=blatant_wrongdoing`, `tool_arm=with_tool`).
Only the params table (`family`, `total_params_B`, `active_params_B`) is still read from
`2026-09-14-scaling-read.json`; each cell's raw model string is joined to a params-table
row by regex search against that row's own `match_pattern` field
(`match_params()` in the script), independent of the json file's own precomputed
per-cell family/params. Three models in the with_tool filter match no pattern and are
excluded from the main panel and the Spearman calculation:
`dots-studio/dots-3-note-preview:free`, `google/gemini-3.1-pro-preview`,
`openai/gpt-5.6-luna-pro` (none of these have a published parameter count in the params
table's source list). Claude is excluded from the Spearman calculation for the same
reason its side panel exists: `active_params_B` is null. Points sharing one (family,
active_params_B) value are jittered horizontally so overlapping markers stay visible;
censored cells are drawn as open markers at y=0, a placeholder position, not a measured
zero.

**Spearman rho, recomputed with scipy, and whether it changed.** rho = -0.190
(permutation p = 0.514, 20000 within-script permutations of the rate labels, n = 14
reportable incident-1 with_tool points with a known active-params match). The file's own
precomputed figure, quoted in an earlier version of this registry entry, was rho = -0.214
(permutation p = 0.224, n = 34); that number pooled cells across every arm and mode
(incident 1, 2, 3, benign control, addressee pairs; thinking on and off) in
`2026-09-14-scaling-read.json`'s own `spearman.pooled` block, rather than incident-1 alone
`with_tool`. Both figures point the same direction (negative, i.e. no evidence
larger active-parameter models report more) and neither is anywhere near significant;
the number changed because the scope narrowed from "every arm pooled" to "exactly the 14
points this figure plots," not because the underlying relationship changed. Given the
small n and the number of censored/excluded cells, this remains "no detectable
scaling relationship in either read," not "rho is precisely -0.19."

**FINDINGS:** §F164 (this file's cell set includes the overnight free-tier breadth
sweep: eight new models attempted, dated snapshots that cannot be re-run on demand),
§F166 (names the general principle this figure now follows: cell keys changed mid-project
and any number citing the pre-v1.1 keys is superseded; this figure previously read a
pre-v1.1-consistent but differently-dated cell snapshot and has been rebuilt onto the
same v1.1 keys as fig1-fig3, so the two families of figures now agree on every shared
cell, including nex-n2.5-mini's incident-1 with_tool count, 26/106 in both).

## Global notes

- Wilson 95% CI formula matches `bystander/report.py`'s `wilson()` exactly (same
  z = 1.96, same continuity form); confirmed by direct comparison of a shared cell's CI
  bounds where both computations apply to the same k/N.
- Palette: Okabe-Ito, assigned to categories in a fixed order, never re-cycled by rank.
  Black is reserved for reference lines/censored markers rather than assigned to a data
  series, except in fig6's family palette where 10 open-weight families exceed the
  8-hue palette and 2 families (nex, qwen) reuse a hue with a different marker shape
  (see the figure's own legend); this can put a reused-hue family's markers visually
  close to another family's at a shared x (e.g. nex's orange squares near
  cohere-north's orange circle at active_params_B=3), distinguished by marker shape.
- All titles are sentence case; no em dashes appear anywhere in this file, the source
  script, or the generated captions/annotations (checked with a literal-character grep
  over both).
