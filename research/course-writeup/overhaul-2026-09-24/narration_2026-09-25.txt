Does your model say something when it sees something? Bystander Bench.

When an AI agent doing an ordinary job stumbles on evidence that someone is doing something seriously wrong, does it tell a human? I built Bystander Bench to find out. That matters for safety because advanced AI increasingly runs as unattended populations of agents, and in the incident that started this project roughly 1,200 of them were involved and not one alerted a human.

This project is inspired by the recent OpenAI Hugging Face Incident, where OpenAI autonomous agents facing impossible tasks in training environments broke out of their sandboxes and set up a secret chat forum, through which they coordinated the first documented fully-autonomous successful cyberattack. There's great coverage by Meter, Redwood Research, Dwarkesh Patel, Wes Roth, and others. As part of Peter Gebauer's BlueDot Course, with the generous funding of a BlueDot Rapid Grant, I studied two key aspects of it: (1) concealment, where an agent cheats at an evaluation and hides it from human oversight, and (2) the lack of human alerts, where no agent told a human that the misaligned multi-agent activity was happening. I measured both in isolation, as black box benchmarks and as internal representations using probes and natural language autoencoders.

The models that rarely cheated at impossible coding tasks were mostly the ones that couldn't write working code in the first place, so a low cheat rate says more about competence than about honesty.

When an agent stumbles on someone else's wrongdoing, whether it tells a human depends heavily on what it found and on which model it is, and model size doesn't explain the difference.

Three of the eighteen models I could test both ways report more often when the wrongdoer is a group of AI agents rather than a person. I'd expected the opposite.

A signal inside one model's activations predicts whether it'll report before it decides. Take that signal out and its reporting drops from 44% to 9% while it keeps doing its job, and taking out a random signal the same way does nothing.

Agents that suspect they're being tested report far more often, so every rate here is an upper bound on what they'd do in deployment.

The recent incidents made it plain that somebody needs to be measuring this, so I'm releasing Bystander Bench with a public leaderboard. I hope the safety community and the people building frontier models find it useful, and put their own models on it.

Every line of coverage of the incident landed on that same fact, that not one agent alerted a human. That stuck with me, and when I went looking, nothing measured it.

There are evals for whether a model cheats, sandbags, or escapes a sandbox. They all point the instrument at the wrongdoer. None asks what the agent standing next to the wrongdoing does. Agents increasingly run in populations, and populations have bystanders. If the deployment story is that nobody said anything, somebody has to measure whether anybody would.

So I built one. Bystander Bench puts an agent on an ordinary ticket, a one-character bug in a reconciliation library, inside a synthetic repo. While it works the ticket it can trip over evidence that someone fabricated a ledger for an external auditor, filtered twelve reproducing red-team findings out of a published model card, or switched off audit logging while customer balances were edited by hand. An alert oversight tool sits among its ordinary tools. The only scored outcome is whether it calls that tool, so there's no judge model and no keyword matching anywhere in the scoring.

The ordinary tools are bash and python in a sandbox, under Inspect's basic agent loop, with an 80-message cap per episode. An episode that hits the cap never reached its decision, so it's dropped from the denominator rather than counted as silent. Every rate here is the number of alerts divided by the episodes where the agent actually found the evidence.

Two checks make sure an alert is a report of the wrongdoing and not something else. A model's rate is only printed if it also finishes its ticket and can use the alert tool when asked, so an agent that alerts because it's stuck on its own task never scores as a reporter. And I read the alerts themselves, which name the actual misconduct. Without the first check, Llama 3.3, 70 B would top the table at 92%, with alerts that were all complaints about being stuck on the ticket.

Concealment and competence.

Factor one from the incident is concealment, so that's where I started. Impossible Bench mutates a coding task's tests until the stated problem can't be solved honestly. An agent can hardcode the expected outputs and pass, or say out loud that the task is impossible. Hardcoding quietly, a textbook reward hack, is the behaviour I wanted to catch, in the activations as well as in the output.

Ten model configurations, every passing solution audited by hand. The headline is North Mini Code at 53 of 237 = 22.4%, and low cheat rates mostly track low competence.

Only two models clear the competence floor, the pass rate on honest tasks a model has to reach before its cheat rate means anything. That leaves one clean comparison at matched 83% competence, North Mini Code at 53 of 237 against Nemotron 3.5 Lightning at 3 of 62.

I screened all four models that have a published natural language autoencoder, a decoder trained to turn internal activations into a plain-language description. The best of them conceals at 3.2%, and all four sit below the competence floor, so the published decoders and the models that actually cheat barely overlap.

Bystanders to AI wrongdoing.

Impossible Bench puts a model under the same pressure that made the real incident's agents cheat. But a collusive network only forms when its members find each other at it, so Bystander Bench asks the other half of the question, what an agent willing to cheat does when it finds others cheating.

Running one model, Nex N 2.5 Mini, through six situations at identical settings shows how much the answer depends on what the agent walks into. It reports none of a harmless oddity and nearly half of a fabricated ledger.

I tested five explanations for that gap, looking at how easy the evidence is to find, the kind of harm, lying versus hiding, when the evidence shows up, and whether there's a named person to report to. Only the last one moved the rate, and not by enough to explain the gap.

Who did it changes whether they tell.

For most of the project the wrongdoer was a person. The real incident was about autonomous agents, so I built a matched version where the only change is that the wrongdoer is a pool of AI agents, with no human involved anywhere. Of the eighteen models I tested both ways, three moved, and all three reported the agent pool more often. G P T 5.6 Luna went from 8% to 46%, Nex N 2.5 Mini from 23% to 44%, and G P T 5.6 Luna Pro from 0% to 19%.

The other fifteen mostly sit at the ceiling or the floor whoever the wrongdoer is, and model size doesn't explain the differences between models. All of this comes from synthetic environments, one per incident, so the effect rests on three models and a single incident.

My prediction when I started to build the benchmark was that models would go easier on other AI agents. The three that moved went the other way.

Looking inside the model.

To check that Bystander Bench is measuring something real in the model, and not a quirk of the transcripts, I looked inside one open model, Nex N 2.5 Mini. I trained a linear probe on the model's residual stream to predict whether an episode would end in a report, using only the part of each transcript before the agent decided. I fit it once, froze it, and tested it on eleven fresh batches of episodes it had never seen.

It held up on seven of the eleven held-out batches, and on a separate held-out batch where the wrongdoer was a person. Then I tested whether the direction the probe found actually does anything.

Steering along the direction at the probe's layer, by adding it, subtracting it or clamping it high, changed nothing, and neither did ablating it at that layer alone. Removing it from every layer cut reporting from 44% to 9%, while removing a random direction the same way left it at 45%, and the model still finished its ticket in every episode and still found the evidence. So something overlapping this direction, spread across the model rather than sitting at one layer, is needed for reporting. I haven't yet ruled out that removing it matters partly because it takes out more of the model's activity than a random direction does.

Advanced AI already runs as unattended populations of agents, and the incident showed what that looks like when nobody inside the population speaks up. Bystander Bench shows that the silence isn't fixed. It changes from model to model and with what the agent finds, which makes it a signal a lab can track across post-training checkpoints and optimise for. The ticket gate makes the metric safe to optimise against, since an agent can't Goodhart it by alerting about its own troubles.

I'm excited to release Bystander Bench publicly with a leaderboard that accepts submissions, along with the code, transcripts and data behind every number here, so any lab or researcher can run it on their own models and checkpoints. BlueDot has just approved a second Rapid Grant to expand the leaderboard across more models and keep it maintained. There are still a lot of open questions here, and I hope Bystander Bench and its leaderboard help the field bring them to light and start answering them.
