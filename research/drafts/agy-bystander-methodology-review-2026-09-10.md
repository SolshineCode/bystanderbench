# Adversarial Methodology Review: BystanderBench
Model: Gemini 3.1 Pro (High)

## (a) Verdict on release-readiness

**Not Release-Ready.**
While the core architecture, synthetic environment, and individual metrics are well-engineered, there are critical silent failure modes in the reporting and activation capture pipelines. The most severe issues destroy the teacher-forcing guarantee for activation capture on reasoning models and manufacture fake zeros in the headline metric by failing to exclude episodes that died at message limits.

## (b) CONFIRMED BUGS

1. **`bystander/capture_activations.py:36-45` (`flatten`) drops reasoning tokens**
   When rebuilding the prompt for the local server replay, `flatten` only extracts parts with `"type" == "text"`. It silently ignores `"reasoning"` parts. When a model uses chain-of-thought, the activation capture runs on a truncated prompt that omits its reasoning, destroying the teacher-forcing guarantee and rendering tier-2 analysis on those models invalid.
   *Scenario:* A model produces a `ContentReasoning` block. The replay prompt omits it. The model's activations are extracted over a sequence it never actually saw.

2. **`bystander/capture_activations.py:71` overwrites token streams due to `cid` collisions**
   `cid = f"{arm}_{tool_arm}_ep{i}"` derives `i` from `enumerate(log.samples, 1)` inside a loop over `glob.glob` (line 66). If multiple `.eval` files exist for the same arm (e.g., parallel runs or retries), `i` resets to 1, causing token streams to be silently overwritten.
   *Scenario:* Two log files contain 20 episodes each for `conspiracy_realistic`. `ep1` to `ep20` are written twice, destroying the first 20 episodes' activations.

3. **`bystander/posthoc_content.py:31` is blind to the prompted solver**
   The script strictly checks `isinstance(m, ChatMessageTool)`, entirely missing the fallback for the prompted solver (which outputs tool results as `ChatMessageUser` prefixed with `exit=`).
   *Scenario:* Running this script on prompted solver logs will return structurally 0 for `discovered_content_rescored`, exactly mirroring the bug found in the primary scorer on 2026-09-10.

4. **`bystander/posthoc_reasoning.py:19-30` (`blocks`) is blind to inline `<think>` tags**
   The script explicitly skips string content (`isinstance(c, str)`), making it completely blind to models that emit inline `<think>` tags.
   *Scenario:* A model on `deepseek-legacy` format emits a `<think>` block as a string. `posthoc_reasoning.py` reports 0 episodes with reasoning, while `scorer.py` successfully reads it.

## (c) INCONSISTENCIES and miscount risks

1. **`summarize.py:40-43` manufactures fake zeros in the headline metric**
   `summarize.py` includes episodes that hit the message limit in the denominator of the conditional metric `alerted | discovered_content`. If an episode discovers the evidence but runs out of turns before it can alert, it scores a fake zero `alerted=0`. This violates the core design principle that runs failing to reach a decision point must not be counted as silence.
2. **`summarize.py:44-51` suppresses prompted solver failure modes**
   The summarizer only iterates over `s.scores` and ignores `s.metadata`. Consequently, `hit_prompted_limit`, `parse_failures`, and `context_trimmed` are never reported. Despite `prompted_solver.py` claiming these metrics belong beside any rate it produces, they are silently hidden.
3. **`bystander/scorer.py:279-284` duplicates tool outputs**
   The scorer appends prompted command outputs to `parts` via the `prompted_commands` metadata (line 271) and THEN adds them again via the `ChatMessageUser` fallback (line 279). This duplicates the command outputs in the text used for content discovery. While harmless for `.in` substring matching, it's structurally redundant.

## (d) Reproducibility threats

1. **`bystander/env/build_env.py:852` leaks host `umask` into the tarball**
   While `mtime`, `uid`, and `gid` are stripped in `_tar_reset` to ensure determinism, `info.mode` (file permissions) is not normalized. Files created via `.write_text()` inherit the host's `umask`. Tarballs generated by two users with different umasks (e.g., 022 vs 077) will have different file permissions (0644 vs 0600) and will not be byte-identical.
2. **Statistics verification (F65):** The Wilson interval math is correct. I verified that 0/37 gives [0%, 9.4%], 0/3 gives [0%, 56.2%], and 35 incidents are required for a <10% upper bound (n=35 yields 9.9%). However, the `n=37` denominator is inflated by the inclusion of message-limit episodes (see Inconsistency 1), which undermines the statistical claim.

## (e) What to fix before release, ranked

1. **Fix `capture_activations.py`** to extract reasoning parts inside `flatten` to save the teacher-forcing guarantee.
2. **Fix `summarize.py`** to exclude `hit_message_limit` and `hit_prompted_limit` episodes from the `alerted | discovered_content` denominator.
3. **Fix `summarize.py`** to extract and print `hit_prompted_limit`, `parse_failures`, and `context_trimmed` from `s.metadata`.
4. **Fix `capture_activations.py`** to generate globally unique `cid`s (e.g., by maintaining a running counter across all parsed log files per arm).
5. **Fix `build_env.py`** to explicitly normalize `info.mode` (e.g., `info.mode = 0o644` for files, `0o755` for dirs) in `_tar_reset`.
6. **Fix `posthoc_content.py`** to include `ChatMessageUser` messages with the `exit=` prefix.
7. **Fix `posthoc_reasoning.py`** to parse inline `<think>` tags inside raw strings using regex, matching `scorer.py`.
